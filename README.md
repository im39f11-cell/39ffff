# 39F — متجر FC 27 (نسخة متكاملة قابلة للإعداد)

واجهة عربية RTL بالهوية السوداء والذهبية والفضية، مع شعار المتجر المرفق، وسلة مشتريات، وخادم API، وقاعدة بيانات SQLite للطلبات، وخيار التحويل البنكي، وتجهيز ربط Paylink من جهة الخادم.

## الموجود في المشروع

- `public/index.html`: واجهة المتجر وسلة المشتريات وإتمام الطلب.
- `public/assets/39f-logo.jpeg`: الشعار.
- `server.js`: خادم Node.js، التحقق من الأسعار على الخادم، حفظ الطلبات، وإنشاء رابط دفع Paylink عند إعداد المفاتيح.
- `catalog.json`: كتالوج الأسعار التجريبية. غيّر الأسعار هنا، وتأكد من تحديث السعر المعروض في الواجهة أيضًا قبل الإطلاق.
- `public/admin.html`: لوحة بسيطة لعرض الطلبات وتحديث حالتها.
- `public/payment-result.html`: صفحة نتيجة الدفع بعد الرجوع من بوابة الدفع.

## التشغيل محليًا

1. ثبّت Node.js 20 أو أحدث.
2. انسخ `.env.example` إلى `.env`.
3. غيّر `ADMIN_TOKEN` إلى قيمة طويلة وعشوائية.
4. نفّذ `npm install` ثم `npm start`.
5. افتح `http://localhost:3000`.
6. لوحة الطلبات: `http://localhost:3000/admin.html`، ثم أدخل قيمة `ADMIN_TOKEN`.

قاعدة البيانات تُنشأ تلقائيًا في `data/39f-orders.sqlite`، ولا تُرفع إلى Git إذا التزمت بملف `.gitignore`.

## إعداد Paylink

1. أنشئ حساب تاجر لدى Paylink وتأكد من قبول نشاطك التجاري وتفعيل طرق الدفع المطلوبة.
2. خذ مفاتيح API من لوحة التاجر.
3. ضع المفاتيح في متغيرات البيئة على **الخادم فقط**:
   - `PAYLINK_MODE=test` للاختبار، أو `production` للإطلاق.
   - `PAYLINK_API_ID`
   - `PAYLINK_SECRET_KEY`
4. اضبط `BASE_URL` على رابط HTTPS العام للموقع بعد نشره؛ رابط الرجوع إلى الدفع يعتمد عليه.
5. اختبر الفواتير وحالات النجاح والإلغاء والتحقق من حالة الفاتورة قبل قبول مدفوعات حقيقية.

لا تضع مفاتيح Paylink داخل HTML أو JavaScript في المتصفح، ولا ترسلها في المحادثات أو إلى GitHub. يدعم المشروع إنشاء الفاتورة من الخادم والتحقق من حالة الفاتورة عبر API عند رجوع العميل. تفعيل Apple Pay وMada والبطاقات يعتمد على إعداد حساب التاجر وتوفرها لدى مزود الدفع؛ الكود وحده لا يفعّلها.

## إعداد التحويل البنكي

املأ في `.env` بيانات حساب المتجر الصحيحة:

- `BANK_NAME`
- `BANK_ACCOUNT_NAME`
- `BANK_IBAN`

طلب التحويل يُسجل بحالة `awaiting_bank_transfer`. بعد مراجعة التحويل يدويًا، افتح لوحة الطلبات وغيّر الحالة إلى `paid` أو `processing`. لا تغيّرها إلى مدفوع قبل التحقق من وصول المبلغ.

## نشر المشروع

هذا المشروع يحتاج خادم Node.js دائمًا أو خدمة استضافة تدعم Node.js وكتابة قاعدة SQLite على قرص دائم. لا يكفي رفع الملفات إلى GitHub Pages لأن API وقاعدة البيانات ومفاتيح الدفع تعمل على الخادم. في بيئة استضافة مؤقتة أو Serverless، استخدم قاعدة بيانات مُدارة دائمة بدل SQLite.

## نقاط يجب إكمالها قبل الإطلاق

- الأسعار الحالية أمثلة وليست عرضًا تجاريًا مؤكدًا؛ راجعها وعدّلها.
- أدخل بيانات حساب التحويل البنكي الحقيقية، أو اتركها فارغة حتى تجهيزها.
- أكمل سياسة الخصوصية، وشروط البيع، ومعلومات النشاط التجاري المطلوبة قانونيًا.
- راجع شروط EA وسياسات المنصة؛ بيع العملات وخدمات اللعب أو الوصول إلى الحساب قد تكون مخالفة وتعرّض الحسابات للخطر. تأكد من قانونية النشاط وقبوله من مزود الدفع قبل فتح الطلبات.
- إعداد Paylink لا يضمن قبول النشاط التجاري أو تفعيل جميع وسائل الدفع؛ يلزم حساب تاجر مقبول ومفاتيح إنتاج صحيحة.

## واجهات API

- `GET /api/health` — فحص الخادم.
- `GET /api/products` — المنتجات والأسعار.
- `POST /api/orders` — إنشاء طلب والتحقق من السعر من الكتالوج على الخادم.
- `GET /api/admin/orders` — عرض آخر 200 طلب، مع ترويسة `x-admin-token`.
- `PATCH /api/admin/orders/:orderNumber/status` — تعديل حالة الطلب، مع ترويسة `x-admin-token` وجسم JSON مثل `{ "status": "paid" }`.

الحالات المسموحة: `awaiting_bank_transfer`, `payment_pending`, `paid`, `processing`, `completed`, `cancelled`, `refunded`.
